# Shared ledger app review brief

Mode: Operate. Scope: implement the approved first-priority features and present a working local review.

The approved information structure is overview, expenses and settlements, with the ledger as the current scope and members as an adjacent task. Desktop uses a compact left navigation, a spacious main column and a useful secondary column; mobile uses a single column and bottom navigation. Expense entry follows amount, purpose, payer, participants, then a calculated preview. A standalone member invitation view supports claim and owner approval.

Visual direction: calm everyday shared ledger. Warm neutral canvas, solid light content surfaces, forest-green active controls, strong ink typography and aligned monetary figures. The material is a well-kept account book without decorative paper textures. Use restrained geometry, divider-led lists, and a single action hierarchy. Background tokens are separate from content-surface tokens for future background settings. No ornamental charts, autoplay motion or stock photographs.

This session builds directly from the accepted layout proposal into code for review; it does not save a standing image-first/code-first preference. All numbers in the demo are illustrative and labeled as such. Cloud mode requires sign-in and the new security rules; local review does not deploy them.

Required review: desktop and mobile layout, keyboard/dialog behavior, expense creation, ledger/member creation, invitation claim/approval, partial repayment/reversal and settlement copy/download. Existing calculation and permission regressions must remain valid. Review the built screens once as a batch, correct material issues, and confirm that batch.
