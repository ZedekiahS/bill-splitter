## 2. 准备与执行顺序

### 环境与账号

1. 使用独立测试数据库和测试账本；不得用手机正在记真实消费的数据库运行重置测试。
2. 准备 A（管理员）、B、C（普通成员）、D（未加入账本的外部账号）。另留临时成员“小林”，用于未注册人员和认领测试。
3. A 在电脑主浏览器；B 在另一个浏览器配置文件；C 在手机；D 在独立配置文件。另开 A2，模拟 A 的第二台设备。普通同浏览器标签页共享登录，不能当成两个独立账号；同浏览器的多个无痕窗口也可能共享会话。
4. 创建独立账本：`三人旅行-CNY`、`个人日常-CNY`、`旅行-USD`、`恢复副本`。故障测试单独建账本，避免前一个用例改变后一个的期望。
5. 准备：小 JPG/PNG/WebP、有效 PDF、超过限制的图片/PDF、损坏文件、中文及同名文件、含历史附件的完整 ZIP、无附件 JSON。不要使用真实证件或付款截图。
6. 全部账号连接同一个后端。不能用 `?demo=1` 验证跨设备共享。
7. 手机可连电脑同一 Wi-Fi 的私有 IP，不要求先公开上线。旧聊天中的 IP/端口可能变化，以启动时打印地址为准。桌面和手机统一使用该地址，以免不同来源的 Cookie/草稿被误当作丢失。

### 推荐顺序

先跑自动测试 → 单人入门 → 三人完整流程 → 退款/预算/报表 → 草稿和并发故障 → 附件/导入恢复 → 手机/中英界面 → 部署验收。

每个失败先记录输入与结果，不直接改测试账目“凑平”。涉及金额、越权、重复写入、附件泄漏或数据丢失的失败应阻止本轮验收通过。

## 3. 固定金额样本：所有人都能手算复核

### 样本一：三人消费、不同垫付人

先不做任何还款，依次录入：

| 账单 | 垫付 | 总额 | A 承担 | B 承担 | C 承担 |
| --- | --- | ---: | ---: | ---: | ---: |
| 晚餐，三人均分 | A | 300.00 | 100.00 | 100.00 | 100.00 |
| 打车，A/B 均分 | B | 90.00 | 45.00 | 45.00 | 0.00 |
| 住宿，按金额分 | C | 600.00 | 200.00 | 150.00 | 250.00 |
| 合计 | — | **990.00** | **345.00** | **295.00** | **350.00** |

| 成员 | 垫付 | 实际消费 | 净余额（正为净待收） | 未抵扣的待收/待付 |
| --- | ---: | ---: | ---: | --- |
| A | 300.00 | 345.00 | -45.00 | 待收 B 100、C 100；待付 B 45、C 200 |
| B | 90.00 | 295.00 | -205.00 | 待收 A 45；待付 A 100、C 150 |
| C | 600.00 | 350.00 | +250.00 | 待收 A 200、B 150；待付 A 100 |

净余额合计必须为 0。实际待结方向共五笔，不能因净额相抵而自动结清。让对应收款人逐笔确认上述五笔，最后所有待收/待付归零，而消费仍为 345/295/350，总支出仍为 990。

### 样本二：已结清账单发生多次退款

独立账本：A 垫付 600，三人各 200；B/C 各还 A 200 并确认。

1. 商家向 A 退款 150，三人各受益 50：净消费各 150；A 应分别返还 B/C 50，原还款记录不变。
2. B/C 确认分别收到返还 50：待结全部为零。
3. 再退款 90，三人各受益 30：净消费各 120；A 又应分别返还 B/C 30。
4. 返还后归零；原消费 600、累计商家退款 240、净消费 360。不能把返还 160 再算成商家退款或消费。

### 样本三：部分还款再多次退款

独立账本：A 垫付 600，三人各 200；B 先还 80，C 未还。

1. 退款 300，三人各受益 100：B 尚欠 A 20，C 尚欠 A 100。
2. 再退款 150，三人各受益 50：A 应返还 B 30，C 尚欠 A 50。
3. B 确认收到返还 30，A 确认收到 C 的 50：全部结清，三人净消费各 50。

## 4. 账号、登录与恢复

| 编号 | 操作步骤 | 预期结果 |
| --- | --- | --- |
| A01 | 新账号输入昵称、有效邮箱、符合长度的密码注册；退出后登录 | 注册/登录成功；进入本人数据；密码不出现在页面或日志 |
| A02 | 分别提交空昵称、非法邮箱、过短/过长密码、已使用邮箱 | 就地显示可操作错误；不创建半个账号、不丢其他已填内容 |
| A03 | 正确邮箱+错误密码、正确密码登录、反复失败触发限制 | 错误不登录；正常组合可登录；限制生效并按窗口恢复，不能靠前端绕开 |
| A04 | A 登录两台设备；其中一台退出；用已撤销 Cookie 再请求 | 对应会话不能继续访问；账号切换后不显示上个账号的账本或草稿 |
| A05 | 模拟会话过期后读取、保存；重新登录 | 不伪装保存成功；引导重新登录；可恢复本人输入，不能拿旧会话写数据 |
| A06 | 使用当前密码生成新恢复码；用旧码、错误码，再用新码重设密码 | 旧码/错误码失败；新码只成功一次；旧密码及所有旧会话失效 |
| A07 | 无账号打开 app、私有账本链接、附件链接 | 要求登录或拒绝访问；不泄漏账本/附件内容 |

恢复码使用合成账号测试，不在截图、文档或对话里记录真实密码/恢复码。邮箱目前只是未验证的登录标识，不把邮件验证当作已实现功能。

## 8. 草稿、失败恢复与编辑器生命周期

| 编号 | 操作步骤 | 预期结果 |
| --- | --- | --- |
| D01 | 填半笔（含比例、备注、附件），关闭、刷新、再打开 | 草稿恢复可继续；字段清空后也保存“空”，不复活旧值 |
| D02 | A/B、不同账本、普通记账、不同模板来源、连续下一笔分别留草稿 | 草稿按账号、账本、来源隔离，不互相覆盖或串用 |
| D03 | 两标签页编辑同一草稿；旧写入迟到 | 不静默覆盖较新输入；冲突或恢复行为可理解 |
| D04 | 模拟 IndexedDB 写失败、空间不足或不可用 | 不假称已保存草稿；当前输入仍可修改/复制，错误出现在相关表单 |
| D05 | 填组合名/批量名单/逐项待分配后直接主保存、关闭、回来 | 未完成内容可恢复；必须确认或明确放弃后才完成账单保存 |
| D06 | 编辑时自动同步、切语言、打开替代窗口、按 Esc/Back | 输入、焦点、分配意图不被旧异步结果替换；焦点合理返回触发处 |

草稿只保存在当前设备/站点来源，不要求跨设备同步；清除浏览器站点数据会删除草稿，不能拿它当服务器丢账证据。

真机要求至少实际测试一台主要使用的手机；桌面窄屏模拟不代替 Safari/Chrome 的软键盘、相机、剪贴板和下载管理。

## 21. 自动化执行与功能对应

在仓库根目录使用 Node.js 22+；依赖未安装时先 `npm ci`。不要为跑测试更换用户正在使用的数据库配置。

```powershell
# 不需要 PostgreSQL；其中部分 HTTP 测试会打开并关闭回环临时端口。
npm test

# 定点下载、日志及静态边界检查。
node --test tests/server-boundaries.test.mjs

# 仅在 .env.test 指向独立、可丢弃的本机 *_test 数据库时执行。
npm run test:api
```

**API 套件会迁移并 TRUNCATE 所配置数据库中的测试表。** 仅文件名 `.env.test` 不保证隔离，必须检查实际 TEST_DATABASE_URL 和数据库用途。API 两个文件顺序运行；不可与使用同一数据库的手机验收服务同时执行。配置密码仅放被忽略的本地环境文件，不粘贴到测试报告。

| bill-calculations、ledger-core | E、H、S | 金额守恒、舍入、原版与当前账本、份额/日期/余额 |

- 权限、重复提交、并发更正、退款及备份无数据损坏/泄漏；任何金额或身份异常均已解决。
- 正常功能及必要错误恢复均可完成，不能只验成功路径。
- 多设备自动同步可用，输入、草稿和日期不被旧响应覆盖。
- 手机和中英各有实际操作证据；未支持能力准确说明，不伪装成功。
- 发布验收另需 O 类实际部署证据；本地通过不等于已经上线可用。

修复失败项后重跑该用例及受影响的相邻流程；只改文档不重复跑业务测试。最后保存具体版本、测试输出、脱敏截图/请求编号及未测范围，不仅写“全部通过”。
