# Bill Splitter：布局与功能方向讨论稿

日期：2026-09-18。状态：设计建议，未实施、未确认为产品规范。

本稿基于当前源码、此前登录页截图及官方产品资料。未登录验证真实账单页面；登录后问题依据代码结构判断。金额、日期及权限已有本地修复，本文不把它们重复列作未修缺陷。本轮不改应用代码。

## 定位假设

暂按朋友聚餐、合租与旅行的共同费用分析；家庭共同记账或个人账本为主的定位仍待用户选择。建议围绕“看清往来、快速记一笔、方便结清”组织功能。

平台仍为网页，优先照顾手机浏览器，桌面支持更高效的浏览与核对。未来 +86、微信、QQ 登录是已提出的方向，本轮不提前选认证供应商。

## 当前页面最值得改变的地方

| 当前结构 | 用户需要 | 建议 |
| --- | --- | --- |
| 首页主要是三个跳转按钮 | 打开就知道自己需要处理什么 | 待收、待付汇总，待办人员，近期账单，突出“记一笔” |
| 历史页以整单金额和全员付款状态为主 | 分清整单总额与自己的往来金额 | 每行突出“你待付/你待收”；总额与垫付人作补充；增加全部与结清筛选 |
| 未付页只有我欠别人的账 | 同时管理付款与收款 | 合并到“结算”，分“我待付”和“待收回” |
| 创建表单先姓名日期，后金额；使用 Ctrl 多选 | 单手快速填写，保存前确认每人金额 | 金额与用途优先；成员复选列表；实时分摊预览 |
| 详情是禁用表单；确认收款需进入编辑再保存 | 看懂账单、直接完成一次明确操作 | 阅读态详情、成员明细；授权收款人单独“确认收款”；编辑次级化 |
| 打开短信/邮件草稿却提示已发送 | 知道实际发生了什么 | 改为“已打开提醒草稿”，可复制分享；不把打开外部应用当送达 |

## 首版页面布局

当前阶段导航用“总览 / 账单 / 结算”，个人设置放头像内。“记一笔”保持全局可见。共享账本实现后，将账本作为页面内的范围选择；暂不为了未实现功能增加空导航。

- **总览：** 顶部范围与新增入口；待收、待付两个主金额；需要处理的事项；最近账单。图表不占据首屏。多币种上线后分币种显示，不能直接混加。
- **账单：** 搜索与“全部 / 我垫付 / 我参与”筛选，再提供结清状态与日期范围。列表显示用途、往来对象、我的金额和状态；选中后查看详情。
- **记一笔：** 金额 → 用途 → 谁垫付 → 谁参与 → 分摊预览。日期默认今天，备注与附件展开填写。均分是快捷入口，自定义金额、比例、份数逐步增加。
- **账单详情：** 用途、总额与日期；垫付人；每个参与人的承担金额、已还与未还；收款确认与修改记录。查看与编辑分开。
- **结算：** 按人汇总待付/待收，展开查看原始账单，提供确认收款或记录还款。后续再加入抵扣建议，始终保留原始账单。

手机采用单列内容、底部三项导航，创建页底部保留合计与保存。桌面使用相同导航的左侧栏，账单列表与详情并排；创建页左侧填写、右侧预览。不要把宽桌面表单直接缩小到手机。

特别需要明确“垫付”和“消费参与”不是同一件事。当前均分排除付款人，新设计若让付款人也参与分摊，属于业务能力调整；应显式展示选择与自付金额，并保持历史账单原份额不变。

## 视觉建议

采用简洁、可信、稍有温度的账本风格。优先考虑白色/浅暖灰内容底、清晰深色文字，原有酒红可缩为主操作与选中态的强调色，不必立刻放弃已有识别。字体使用一致的中英文无衬线组合，金额使用等宽数字并右对齐。

列表与留白承担主要层级，不把每条记录包装成厚重卡片；每屏一个明确主操作。待付是正常业务状态，不全部染成警告红。颜色必须配合“待付、待收、已结清”等文字。错误出现在对应字段附近，保存有进度及结果，空状态能引导完成第一笔账。

已参考用户指定的 ui-ux-pro-max、impeccable 和 design-taste-frontend。后者主要针对营销页与作品展示，这里只采用其视觉一致性、避免模板化和依据场景选风格的原则。技能检索首次混入落地页与健康类字体建议，未采用；更精确的检索匹配到 Expense Splitter / Bill Split，适合以余额及结算为重点。

## 拓展优先级

| 顺序 | 功能 | 实际价值与边界 |
| --- | --- | --- |
| 第一批 | 共享账本/活动：合租、旅行、聚餐 | 固定成员和账单范围，账单有归属；需新增成员权限，不能向所有注册用户开放 |
| 第一批 | 邀请与临时成员 | 先用名字记账，之后邀请本人认领；认领需验证，不能按同名自动合并；邀请链接需明确访问范围 |
| 第一批 | 结算流水、部分还款、撤销记录 | 记录何时还了多少，保留修改理由与来源；现有 paid 布尔值不足以表达，需要独立还款记录 |
| 第一批 | 可分享结算单 | 清楚列出谁付给谁、金额和来源，方便发到已有聊天工具；分享前可预览并选择公开范围 |
| 第二批 | 周期账单与模板 | 房租、网费每月生成待确认草稿，少重复输入；不自动把草稿当已发生支出 |
| 第二批 | 收据、备注与逐项分摊 | 保留消费依据，支持有人没吃某道菜等情况；先上传附件，再加 OCR，并要求确认识别结果 |
| 第二批 | 多币种旅行账本 | 保留原币、使用的汇率与结算币种；统一后才汇总，明确汇率来源与时间 |
| 后续 | 离线草稿与同步 | 网络不好时仍可记录；需明确待同步状态，处理重复提交与多人修改冲突 |
| 后续 | 语音/自然语言记账、分类与预算 | 生成可核对草稿，辅助回顾消费；不要直接自动入账或替用户认定还款完成 |

结算抵扣可减少转账次数，例如甲欠乙 100、乙欠丙 100，可提出甲向丙付 100 的方案；这应是可查看依据的建议，不静默修改原账。先做账本内的结算，避免一开始跨账本抵扣。

当前不建议首版加入完整聊天、实际代收付款、投资理财或复杂 AI 助手。优先让多人能顺利加入、看懂自己的金额、知道还款是否确认。
