# 收款重试与编辑恢复收尾

针对 `04e0358` 复核提出的一项 P1 和三项 P2，保持本轮范围为这四个问题。

## 修复

- **收款结果未知**：单笔收款将原始付款方向、金额、日期、备注、账单版本、待收余额和幂等键作为同一次提交保留。网络失败、5xx、回复解析失败后，核实结果仍提交原请求；不会随页面的新余额生成另一笔收款。金额等输入在核实期间只读。当前标签页的会话存储支持关闭窗口、重新打开及页面重载；登录失效、限流或超时不清除未知请求。明确的校验或版本冲突才允许重新核对并提交新请求。未自动重试财务写入。
- **分摊模式切换**：手工总额与项目合计分别保存，草稿记录手工总额。空项目不会覆盖之前的总额；逐项待分配人员在其他模式下隐藏，切回后继续处理。
- **已有组合编辑**：按组合保存名称、成员集合及原始版本；模式切换、折叠、刷新、切换组合和“稍后继续”均保留编辑。存在实际修改时，主账单保存要求先更新或明确放弃组合修改。多人冲突展示最新名称和成员，用户明确核对后才可继续提交；对方删除组合也不会清掉本地编辑。
- **停用成员**：组合定义保留原有停用成员，改名不改变成员集合；应用组合只选活跃成员。后端允许保留原组合中的停用成员，仍拒绝新增停用成员、跨账本成员和已移除成员。全员停用的组合也能改名，恢复成员后可再次应用。

## 验证

新增回归先在旧代码上失败：`node --test tests/editor-recovery.test.mjs tests/invitation-navigation.test.mjs`，覆盖总额变空、待分配状态消失、组合编辑被重绘覆盖、停用成员被移除和收款回复丢失。修复后通过。

- `npm test`：16 个测试文件，**223 项通过，0 失败**。新增 jsdom 开发依赖，让编辑器测试直接运行实际 HTML、事件和草稿保存代码；不进入产品运行依赖。
- 隔离 PostgreSQL API 测试：**56 项通过，0 失败**。使用独立 `entry_regression_20261106` schema，没有清空手机使用的账本。
- 三个真实登录账号：分别模拟发送前断网、服务端成功提交后丢失回复、成功回复无法解析、提交后返回服务错误；每种情况连续失败两次后重试，并模拟标签页重载及用户输入变化。最终每笔只有一条 50 元收款，欠款仍为 50 元，三个账号读取完全一致。
- 多账号组合维护：停用组合全部成员后由组合创建者改名，成员定义不变；旧版本更新、新增停用成员及外部成员被拒绝；恢复成员后原组合完整保留。
- 两个独立浏览器登录会话：100 元按 60/40 分摊，切到空白逐项再切回；修改组合名称，退出并恢复；主保存拦住未保存的组合编辑。更新组合后另一账号应用旧版本被要求核对；保存账单后另一账号自动显示相同的 100 元及 60/40 明细。
- 组合编辑还覆盖多个未保存组合、明确放弃、对方改名/删组以及恢复草稿后的并发版本检查。中英文消息覆盖测试通过。

## 边界

没有公开部署，没有真机软键盘或文件选择器验收。故障测试在实际 API 客户端和本地 PostgreSQL 服务之间确定性注入，不是拔网线测试。会话存储被浏览器禁用时仍有当前页面内的重试保护，但无法保证重载后恢复未知操作；关闭整个标签页后也不承诺恢复其会话状态。批量收款、成员页新入口和备份上传体验未在本轮扩展。
