# 同页报告读取顺序 — 2026-11-10

针对 `8acdda7` 复核中的既有 P3：普通／恢复加载与后台同步同时读取报告时，同一报告序号下的迟到旧快照仍能覆盖已显示的新金额。

## 复现与修复

修复前运行 `node --test --test-name-pattern='older same-page background' tests/report-state.test.mjs`，普通加载与恢复加载两条测试均失败：页面先显示 75 元，释放迟到的后台响应后变成 35 元。

没有按金额大小判断数据新旧，也没有仅按请求发出顺序猜测服务端快照的新旧。改为避免同页前台和后台读取并行提交：

- 报告容器仍为 `aria-busy="true"` 时，自动同步暂缓读取。同步请求中途也沿用有效性检查；新页面／保存操作仍使原响应失效。
- 当前前台读取成功或失败后，清除加载状态并唤醒同步，处理尚未消费的修订。
- 过期读取不能清除当前加载状态或唤醒同步；后台已经取得的数据在挂载时不会再次唤醒自身，避免立即轮询循环。
- 保留保存失败后的替代读取、错误重试、日期未提交保护和筛选状态。

## 验证

新增五项回归，使用真实应用 HTML、app.mjs、报告组件、hashchange、自动同步调度器与受控 Promise／计时器：

1. 普通加载期间后台同步等待；显示 75 元后，不被旧 35 元覆盖。
2. 保存失败后的恢复读取期间同样保护。
3. 前台读取失败时提供重试入口并唤醒同步；未处理修订仍能读取，之后不反复读取相同报告。
4. 旧成功响应先返回时，不提前结束恢复读取的加载状态，也不放行后台请求。
5. 旧错误响应先返回时，同样不放行；当前读取完成后正常恢复。
