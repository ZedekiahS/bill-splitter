# 共享账本自动同步验收 · 2026-10-30

共享账本现在会自动更新：页面可见时约每 3 秒查询一次修订号，有变化才加载
账本内容；回到页面、网络恢复时立即检查。没有新增环境横幅或反复弹出的同步提示。
这属于短间隔自动同步，不是毫秒级推送。

## 实现边界

- PostgreSQL 为账本保存递增的 `revision`。账单、收款、撤销、模板和成员操作
  与修订号在同一事务内提交；失败操作和幂等重放不增加修订号。
- `/api/ledger-updates` 只返回当前登录者已加入账本的 ID 和修订号，不提供金额、
  邀请或其他人的账本信息。每次查询仍检查会话。
- 同步一次只发起一轮读取，隐藏页面暂停；读取失败按 6/12/24/30 秒退避，成功
  后恢复 3 秒。GET 请求有 15 秒超时，避免卡住后无法恢复。同步不会重试财务写入。
- 正在填写的账单、金额和备注不重建。收款表单仅更新剩余待收提示；只读账单
  详情和结算单更新内容，复制/下载读取更新后的文本。
- 保存中、账本切换中暂缓同步；搜索框或账本选择框操作结束后补查。晚到的旧
  响应不能覆盖新选择或已退出的状态。保留当前筛选、视图和页面滚动位置。
- 会话失效时停止同步、清除可见账本并显示登录入口。邀请批准带来的成员列表
  变化也能让等待认领的页面自动进入已获准的账本。

已有数据库更新代码后须先运行 `npm run db:migrate` 再启动服务。迁移新增一个
修订号列，保留现有账户、账本和流水。本机开发数据库已执行此迁移；没有公网部署。

## 自动化验证

`npm test` 的 170 项检查、`npm run test:api` 的 30 项检查通过，共 **200 项**。
相对于上一轮新增 10 项：

- 5 项同步调度检查：不重叠、隐藏与恢复、网络退避、会话失效、离开页面后的清理。
- 4 项实际应用处理函数检查：变化只加载一次、旧响应隔离、搜索/保存期间延后、
  弹窗数据更新。
- 1 项真实 HTTP/PostgreSQL 场景，含多项断言：未登录拒绝、外人不可见、批准前
  不泄漏账本、批准后可见，以及记账/收款/撤销/认领后的修订号变化；回滚及重放
  不产生假更新。

旧有财务并发、权限、重试、周期和金额回归继续通过。测试使用独立 `_test`
数据库；开发数据库未用于测试重置。

## 两个独立登录页面的实际操作

通过三个步骤准备合成账号及共享账本：测试 API 注册、建立成员关系、浏览器
分别登录。浏览器分别使用 `owner.localhost:2807` 与 `member.localhost:2807`，
cookie 隔离，连接真实 Node/PostgreSQL 后端。以下接收方均未点击刷新或重新加载：

1. 小周记下 ¥120「周五晚餐」，小林页面自动显示账单和待付 ¥60。
2. 小林打开记账表单，填 ¥88「返程车费」。小周确认晚餐收款 ¥20，小林背景
   余额自动变成待付 ¥40；原表单的 ¥88 和标题保持不变。
3. 小林保存车费，小周页面自动出现 ¥88 账单，个人份额 ¥44。
4. 两边同时打开车费收款表单。小周确认 ¥14，小林表单的剩余待收自动由 ¥44
   变为 ¥30，已填金额仍为 ¥44，未被自动改写或自动提交。
5. 小林打开车费详情。小周撤销 ¥14 收款，小林已打开的详情自动恢复为未还、
   待付 ¥44，流水仍保留更正历史。
6. 小林保持结算单打开。停止测试后端，小周录入 ¥10「停车费」保存失败，
   输入保留。重启后端后小周主动重试保存；小林无需刷新即可看到新往来。
   已打开的结算文本增加停车费 ¥5，复制出的文本也包含该项。
7. 最终总支出 ¥218，小林待收 ¥44、待付 ¥45，净待付 ¥1；小周净待收 ¥1。
8. 在同一创建者会话的另一标签退出，原先打开的账本自动清空，显示登录入口。

验证完成后关闭临时页面和测试服务。截图保存了接收方的最终账本。

## 验证范围

浏览器部分是同一台电脑上的两个独立认证会话，不是实体手机或公网跨地域测试。
隐藏页面、会话过期、旧响应顺序等由自动化检查覆盖；另以浏览器验证了跨标签
退出导致的会话失效。未将这些检查冒充物理设备实测。
本次没有引入 WebSocket/SSE、消息队列或浏览器通知权限，部署仍使用现有同源 API。
