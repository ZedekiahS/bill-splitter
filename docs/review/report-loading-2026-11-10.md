# 个人报告加载恢复 — 2026-11-10

针对 `8082097` 复核中新增的 P2：统计范围保存尚未完成时离开再返回个人页，保存失败使返回后的报告请求失效，而账本修订未变化，自动同步不会重新读取，页面持续停在加载状态。

## 修复

- 保留报告序号和旧响应丢弃机制。
- 报告容器通过 `aria-busy` 表达实际加载状态；当前请求显示内容或错误后清除，过期请求不能清除新请求的加载状态。
- 范围保存结束时，如果仍是同一账号、当前处于个人页、报告容器已因导航替换且仍在加载，立即补发一次报告读取，不依赖账本修订变化。
- 补发读取也沿用旧响应校验；失败时使用已有错误与重试入口。仅重读，不重试写入。
- 原页面的保存结果和错误继续就地处理；返回后的报告已经加载时不强制重绘，保留未提交日期输入。

## 验证

先在未修改产品代码时新增复现，运行 `node --test --test-name-pattern='failed inclusion save recovers' tests/report-state.test.mjs`：按钮导航、真实 hashchange 两条路径均在“报告应替换加载状态”的断言失败。

修复后新增七项回归，使用真实应用 HTML、app.mjs、报告组件、DOM 事件和 `createAutoSync` 调度器，通过可控 Promise 与计时器模拟响应顺序：

1. 保存失败、按钮导航往返、修订保持不变：报告恢复，勾选仍为原值，写入只调用一次。
2. 同样路径使用真实 hashchange。
3. 保存成功、按钮导航往返：恢复为已保存的排除状态，旧响应不恢复旧勾选。
4. 同样成功路径使用真实 hashchange。
5. 补发读取失败：显示错误和重试入口，旧成功响应不覆盖错误；点击重试后正常显示。
6. 返回报告已加载后保存才失败：未提交日期输入和焦点保留，提交日期后后续更新仍正常。
7. 没有导航时保存失败：原地错误和勾选恢复，不额外重读。
