# 记账时添加参与人

手机用户已确认局域网登录可达，并录入 800 元火锅。电脑原页面随后自动出现
该账单（小林垫付，另一个成员待付 480 元），未点击刷新。

问题来自两个限制叠加：表单只列已有成员，没有添加入口；新增临时成员原先
仅限创建者。现在所有已加入账本的成员均可添加临时参与人，入口放在记账表单
和成员页。姓名不等于账号授权，创建邀请和批准认领仍仅限账本创建者。

- 均分添加后勾选新成员并重新计算。
- 按金额/比例保留原输入，新成员分别留空/初始 0，用户决定新份额。
- 逐项分摊新增人选出现在每个项目中，由用户勾选，保留已有项目内容。
- 已收款锁定的财务更正、固定周期确认以及归档账本不放开原有约束。
- 添加期间阻止提交，失败显示就近错误；金额、备注、收据和草稿不被重建。
- 添加即进入账本，取消当前账单也不删除该成员；操作处已说明。

验证：183 项本地测试、42 项 API 测试通过。API 回归使用独立 schema
`entry_regression_20261106`，不含 public 回退路径，未清空手机正在使用的数据。
新增验证普通成员添加/重试、临时身份不授予访问权、邀请仍拒绝、外部账号拒绝、
新成员分摊保存和归档拒绝。

浏览器用普通成员在另外的账本操作：填写 90 元晚餐，直接添加第三人后每人
30 元；刷新恢复草稿再保存成功。在 390×844 窄屏验证按金额 10/20/30 元，
新增第四人后原输入不变，新人留空；明确填 0 后保存成功。原手机火锅账单未修改。
