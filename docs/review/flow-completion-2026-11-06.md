# 账本体验分析：实施与验收清单

日期：2026-11-06。对应「分析账本体验优化」对话中记账、查账、结算以及恢复流程的三轮改进。本清单记录当前结果；[第一轮记录](entry-flow-2026-11-06.md)中的八人限制、固定上海周期时间和测试数量属于当时状态，以本文件为准。

## 逐项结果

| 原分析的问题 | 已实现的行为 |
| --- | --- |
| 添加一人后收起，不能连续添加 | 记账和成员管理均支持连续输入、回车添加；保留焦点，显示已有同名成员供选择，避免重复创建。 |
| 新成员加入后不知道是否承担费用 | 保留原有自定义份额；按当前模式提示填写金额、调整比例或选择消费项目。均分即时重算。 |
| 多人账本默认选择前八人 | 八人以内默认全选，更大账本默认只选自己；提供搜索、计数、清空、全选和上次组合。上次组合排除已停用成员。 |
| 八人上限影响聚餐旅行 | 单笔及逐项参与人上限扩展到 50，前后端一致校验。消费项目仍最多八项。十人账单已通过浏览器实际保存。 |
| 百分比需要重复计算 | 初始均分；两人修改一人自动补足另一人；多人保留已修改比例，在未修改者间分配余数；提供重新均分比例。超出 100% 时阻止提交。 |
| 垫付人最终承担部分不清楚 | 预览显示最终消费份额，包括旧版未分配比例由垫付人承担的部分；百分比同时显示对应金额。 |
| 普通草稿和模板草稿相互覆盖 | 按账号、账本、编辑来源隔离；连续记账使用独立草稿身份。附件与未完成输入可恢复。 |
| 更正冲突恢复成旧版本 | 比较原始版本、本地修改、最新账单；独立字段合并，重叠字段由用户选择。发生还款后禁止覆盖财务字段。 |
| 保存后丢失筛选和位置 | 保存回到原页面并保留查询、筛选与位置；保存并继续保留参与人，清空上一笔内容。 |
| 成员名称错误或成员离开 | 临时成员可按权限改名；无历史引用者可移除；账本创建者可停用和恢复非创建者成员。旧账和查看权限保留；涉及启用模板时要求先调整模板。 |
| 搜索和筛选不足 | 搜索标题和备注；成员及其垫付/参与身份、起止日期、未结清/已结清/已撤销状态可以组合。 |
| 无法查清每个人的账 | 成员往来页显示消费、垫付、已收、已还、待收、待付，以及伙伴间余额，可转到相关账单。 |
| 一次转账要逐笔确认 | 按付款人与收款人汇总；一次确认可以按日期由早到晚分配到多笔账单，提交前展示分配和剩余金额。服务端原子写入、幂等重试、并发冲突复核。 |
| 净余额容易被误认为自动清偿 | 相反方向的欠款分别显示，不自动抵销。一次实际收款显示为一条记录，可查看分配并整体撤销。底层保留每笔账单的关联记录。 |
| 首页待办不突出 | 有实际内容时显示草稿、到期周期账单及待处理认领入口；没有内容时不展示空提示。 |
| 手机入口和长表单不顺 | 成员、结算也能直接记一笔；筛选、成员往来、收款分配及恢复流程按窄屏排版，保存按钮可访问。 |
| 邀请异常路径不足 | 新邀请使旧未使用邀请失效；支持撤销邀请和拒绝认领；过期、撤销、待批准、已拒绝及已加入有对应可操作状态，等待页自动更新。 |
| 周期时间依赖设备或固定时区 | 新账本记录创建时所选时区，创建者可调整；周期日期与还款撤销日期按账本时区计算，已存账单日期不变。旧账本默认上海时区。 |
| 导出后无法恢复 | 支持 JSON/ZIP 预览和导入为新账本；校验金额、引用、还款、历史及附件，保留历史附件。重新生成标识；导入者选择自己的成员身份，其他成员需重新邀请。不会覆盖现有账本。 |
| 忘记密码无恢复路径 | 新注册展示一次性恢复码；已有账号可在账号设置验证密码后生成或轮换。恢复密码消耗恢复码并撤销旧会话。不会伪装发送邮件。 |

## 验证证据

- `npm test`：195 项本地测试通过，覆盖计算、草稿、冲突、语言、筛选、同步、导出和收款分配等十二个测试文件。
- PostgreSQL/API：50 项通过，包括多人权限、重复请求、并发收款、整体撤销、停用与模板限制、邀请状态、账本时区、带历史附件的恢复、恢复码轮换/单次使用及会话失效。
- API 运行使用独立 `entry_regression_20261106` schema，连接搜索路径不回退到 `public`。浏览器流程使用独立 `flow_ui_20261106` schema。测试没有清空手机试用的数据。
- 浏览器独立账号实际操作：连续添加、同名复用、比例补足、保存并继续、草稿隔离、并发更正恢复、筛选保留；收款 80 元分配为两笔 60 + 20，另一账号自动更新；随后整体撤销，两边余额恢复。
- 浏览器下载带附件格式的 ZIP，导入新账本并选择本人，核对成员、模板和余额；停用成员后旧欠款仍保留。十人均分 100.01 元成功保存，上次组合可再次选中十人。
- 390 × 844 窄屏及中文/英文界面复核；没有添加开发、示例环境或交付过程提示。截图保存在本地复核附件中：`settlement-batch-mobile.png`、`percentage-auto-mobile.png`、`percentage-auto-mobile-en.png`、`draft-conflict-review.png`。
- 新版手机预览使用端口 2809；原有 800 元火锅和 80 元午餐记录保留。2807 的浏览器本地草稿不会自动迁移到 2809。

## 仍需明确的边界

真实手机输入法、系统文件选择器和软键盘遮挡需要在手机上复核；桌面窄屏模拟不能替代这一点。局域网服务用于本地复核，未公开部署。

恢复码需要自行妥善保存；同时丢失密码与恢复码，当前没有自助恢复途径。邮件验证/邮件投递、短信、微信和 QQ 尚未接入，不以模拟成功替代。

JSON 本身不携带图片文件；有文件附件的备份需用完整 ZIP。导入会拒绝缺失的当前或历史附件，不静默丢失它们。上传上限 20 MiB，ZIP 解包内容最多 40 MiB、2,000 项。

原分析明确放在后续的扩展已经评估，但本轮未实现：一次粘贴多个名字、多人共同垫付同一笔、额外代记授权、消费分类与旅行汇总、OCR/自然语言录入。它们需要各自的数据及权限设计，不能当作当前缺陷修复悄悄改变账务语义。资产管理、投资、社交功能仍不纳入共同账本核心流程。
