# 可靠性修复验收 · 2026-11-07

范围：针对 `f28b0e2` 新评价中第一轮四项问题修复；连续记账上下文、批量名单等后续体验/扩展不包含在本轮。

## 行为变化

1. **单笔收款**：请求必须包含用户看到的收款人、账单版本和剩余待收金额。任一不一致返回 409，不写付款、不改余额。窗口保留金额、日期和备注，显示最新方向及待收金额，必须勾选重新核对才能继续；再次变更会清除勾选。相同幂等键重试仍返回原付款。
2. **完整备份**：新版页面直接流式上传 ZIP/JSON，逐份处理附件并使用账号绑定的短期预览标识提交。保留历史附件，预览增加完整日期范围、有效支出、待结总额及各成员应收应付。导出和导入共用 64 MiB JSON 元数据限制，附件不计入元数据容量；每份仍为 2 MiB。取消仅导入端存在的记录数量限制。容量与部署边界见[导出格式](../ledger-export-format.md)及[自托管说明](../self-hosting.md)。
3. **状态筛选**：快捷未结清直接设置高级筛选的同一个状态值；切到已结清后快捷状态同步取消，不再将两个互斥条件叠加。与我的关系仍是独立维度。
4. **模板草稿**：空白新模板、从账单 A 创建模板、从账单 B 创建模板各有独立标识；重新打开同一个来源仍恢复自己的草稿。旧草稿不删除，仍可在草稿列表继续编辑。

## 实际边界

使用操作系统临时目录，需要服务器可用磁盘、合适的反向代理上传限制及时间；上传五分钟超时，预览三十分钟失效。多实例需要保持上传和提交落在同一实例。正常完成、失败、过期和关闭服务会清理临时文件；进程崩溃后的残留清理已在部署文档说明。旧 JSON/Base64 接口仅保留兼容，新页面不使用。

桌面窄屏模拟不代表真实手机输入法/系统文件选择器验证。本轮没有公开部署，没有修改真实账本数据，提交与推送按用户指示执行。
